BEFORE-EDIT FINDINGS
Already implemented and supported by baseline tests/source inspection:
AUTH-01 through AUTH-06; AUTHZ-01 through AUTHZ-03; SESS-01 through SESS-03;
CAT-01 through CAT-06 and CAT-08. CAT-07 had documented route changes but two
additional frontend payload regressions discovered during the review.

Incomplete/incorrect:
1. Section 5 request validation: several controllers still used any/interface body
   types with no runtime DTO validation. Invalid booleans, numbers, enums, dates,
   objects and nested stock adjustments could reach handlers/persistence or fail 500.
2. Section 5 HTTP statuses: raw Prisma validation, missing-row and constraint errors
   could escape as 500 responses; explicit duplicate coupon/customer checks used 400.
3. Section 5 sensitive logging: CMS/Prisma logged raw exception objects; upload logs
   included user-derived filenames/URLs and provider error messages; cache logs
   echoed arbitrary caller-supplied prefixes.
4. CAT-07 compatibility: product sizeVariants[].sku sent by the current admin form
   was rejected; the announcement editor round-tripped id/updatedAt, which the
   existing update allowlist rejected.
5. Sections 6-7 automated evidence: these validation/logging/compatibility cases were
   absent. Session HTTP tests used a revoke stub, so did not exercise real service
   ownership enforcement end to end.

CORRECTIONS MADE
- Added runtime class-validator DTOs and strict controller validation for coupon,
  offer, CMS, CRM, inventory, settings, upload and cache request bodies. Missing or
  malformed required fields and unexpected fields produce 400 before handlers run.
- Preserved numeric form strings, optional blank dates/numbers, empty optional CRM
  email and actual false booleans. String "false" is rejected instead of coerced.
- Permitted the existing size-variant SKU field. Rejected null for required catalogue
  scalar strings while retaining nullable categoryId/brandRefId relationships.
- CMS DTOs discard read-only id/createdAt/updatedAt values, preserving the existing
  server identity and timestamps when the editor submits a full object.
- Added a controller-scoped persistence exception filter for products, categories,
  brands, coupons, offers, CRM, settings, inventory and sessions. Known validation
  errors return 400, absent records 404, constraint/concurrency conflicts 409; other
  known Prisma errors stay 500 with a generic message. Raw query/input values are
  neither returned nor logged by this filter. Existing 401/403 exceptions are not
  caught or converted. No global/payment exception behavior was changed.
- Changed duplicate coupon/customer responses to 409. Successful envelopes and
  route paths are unchanged.
- Sanitized the identified explicit logging statements. The PrismaService edit is
  ONE log statement only: schema SQL, startup behavior and connection logic are
  unchanged. Upload edits are DTO/error/logging changes only, not S3 lifecycle or
  infrastructure changes.
- Added 38 focused tests; retained the original 40 tests unchanged.
